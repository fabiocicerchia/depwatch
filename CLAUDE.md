# CLAUDE.md

Guidance for Claude Code (and other AI agents) working in this repo.

## Project

Measures dependencies on two axes and plots them against each other:
**drift** (how far behind, in libyears — objective and computable) and
**viability** (can you even catch up — maintainer activity, bus factor, release
cadence, archived status, funding, last commit). TypeScript in `src/`, built to
`dist/`. The two-axis plot is the product; a single "outdated" number is not.

## Commands

```sh
make help         # every verb this repo exposes
make setup        # Install git hooks and dev tooling
make lint         # Run all pre-commit checks on the whole tree
make build        # Build the project
make test         # Run the tests
make clean        # Remove build artifacts
```

## Conventions

- Match existing style; don't reformat unrelated code.
- Conventional Commits for messages (see CONTRIBUTING.md) — they drive the
  release-please version bump.
- `CHANGELOG.md` is generated by release-please; don't edit it by hand.
- Update `docs/` and `examples/` with behavior changes.
- Never commit secrets; CI runs gitleaks. Keep `.env` out of git.

## Guardrails

- Drift must stay objectively computable — no heuristics in the libyears maths.
- Viability signals are heuristic by nature: each new one needs a stated
  rationale and a test.
- Registry calls are rate-limited and cached; don't add an uncached fetch.
- Don't touch generated files or lockfiles by hand.
- Ask before large refactors or destructive operations.
